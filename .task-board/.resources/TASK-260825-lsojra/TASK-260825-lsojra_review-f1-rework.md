## Root cause and repair

The prior test spawned the real `runtime runtime-launch` process, but its decoder first ran the specified production gate and then evaluated the selected mutant against a constant harness-built plain-valid frame. The process was real; the gate under test did not consume the delivered descriptor-3 bytes. `reject_all_probe` was rejected by the harness allowlist before the gate.

The repair keeps `decodeSharedRuntimeAuthorizationFrame` as the concrete production call site from `RunSharedRuntimeLauncher`. The test-only seam now replaces only the shape decision inside that decoder. Its input is produced by the production tokenizer and carries each member's decoded name, raw wire spelling, and raw value. Production still decides on decoded-name multiset equality against `sharedRuntimeAuthFields`; wire spelling is neither the production decision key nor recorded evidence.

All 18 mutant rule-1/direction/blindness measurements now tokenize the actual generated bytes through the production tokenizer before calling the selected predicate. `reject_all_probe` is a selectable non-gate control at the production entry.
